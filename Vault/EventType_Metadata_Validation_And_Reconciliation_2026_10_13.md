# EventType metadata validation and reconciliation

## October 21: report parentless placeholders without deleting them

Five default SD11 ties (SM478011 through SM478015) contain `["{\"eventType\": \"HIERARCHY\"}"]` with a null parent property. The user explicitly requested retaining these placeholders. Their Getty SD468416 ties independently identify SM3266 as parent. No source repair or live data write was performed.

The old nightly parent-CMID query and Python fallback excluded absent/empty parents; event validation checked the vocabulary but did not require a parent. Consequently updateContains first rejected the incomplete context after earlier processing steps had run. New context writes now require a nonblank string parent, while legacy reconciliation continues to accept the stored source representation. Nightly checks report absent/null/blank/non-string parents in the existing `Invalid parentContext parent CMID` count and spreadsheet, with dataset, CMID, USES Key, parent values, decoded context, and error. Vocabulary-only reporting stays separate. The primary CMID lookup and fallback both restrict nonexistent-reference checks to strings so malformed values are not counted twice.

`updateContains` skips entries with absent/null/blank/non-string parents, continues valid per-parent event/date reconciliation, and never edits the source USES properties. Unknown event types still fail validation. Regression tests cover all malformed parent forms, primary/fallback nightly reporting and attached spreadsheets, unchanged source placeholders, valid event/date pairing, and stale derived event cleanup. Fifty-three focused tests passed. These code changes require a separate authorized production deployment before the API uses them.

The authoritative vocabulary is `(:PROPERTY {CMName: "eventType", type: "relationship", CMID: "CP117"}).allowedValues`. On 2026-10-13, the existing CP117 node in both live SocioMap and ArchaMap was preflighted, updated with `["SPLIT", "MERGED", "SPLITMERGE", "HIERARCHY", "FOLLOWS"]`, and independently queried to verify it. No category or source USES data was changed. The initialization procedure is `scripts/update_event_type_metadata.py`; default execution is read-only, and `--apply` initializes absent values after checking both databases. It refuses to overwrite a different configured vocabulary. Use configuration/environment references for credentials.

`CM/event_types.py` reads the list without caching and rejects missing, duplicate, or malformed metadata. Admin edits, raw/embedded upload values, direct USES creation/property updates, category/USES merging, moving USES ties, and reconciliation use shared validation. New writes reject values outside the exact configured list, including trailing whitespace. Nightly checks read that same metadata and report invalid source parentContext eventTypes as well as derived CONTAINS eventTypes, with source identities and spreadsheet attachments.

The old event cleanup checked whether the child had any parentContext. It left events attached to an old parent when context for another parent remained. `updateContains` now computes unique `(eventType, eventDate)` pairs independently for each parent-child edge and removes both event properties when that pair has no event-bearing source context. Event/date ordering remains aligned; missing dates retain the existing `NULL` sentinel contract. Only requested children are processed, and the write is prepared after all selected source entries validate.

Contextual writes immediately call `processUSES` for CMIDs returned by the actual mutation. Admin selection checks prevent the relationship and form category from disagreeing. Processing failures are propagated instead of reporting success. Source USES writes and reconciliation are separate operations: on processing failure the source remains queued through its `status=update` marker.

Read-only inventory checked 139418 SocioMap source ties and 2425 ArchaMap source ties with parentContext. Nine SocioMap ties fail strict source validation: six have `SPLIT `, two have `Hierarchy`, and SM467023/SD11 (`Name == Kochi (pre-2005)`) has eventDate 2005 without eventType. ArchaMap has none. Reconciliation resolves legacy whitespace/case variants only to an approved metadata term, without changing source USES properties. A legacy date-only context contributes no event; stale derived events for that pair are cleared without guessing a type. New writes reject all these noncanonical/incomplete forms, and nightly source validation reports them. Unknown values fail validation; no invented aliases or fallback vocabulary are used.

Regression coverage includes metadata vocabulary changes without code changes, strict input validation before writes, source reporting, category selection/processing failures, stale events after changing/removing a parent's context, aligned duplicate event/date pairs, and rollback-only Neo4j queries. `tests/event_types_realdb_test.py` changes vocabulary and creates fixtures only inside a transaction that always rolls back, then independently verifies rollback. Running that test explicitly requires `--run-realdb` and the real-DB environment gate. Production code deployment remains a separate authorized operation.
